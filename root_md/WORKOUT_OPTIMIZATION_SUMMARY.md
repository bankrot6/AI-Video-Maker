# Оптимизация загрузки и отображения тренировок

## Проблема
После онбоардинга при переходе на главную страницу пользователь видел только статичные шимеры и ничего больше, хотя первый день тренировки уже был загружен. После hot restart всё отображалось нормально.

## Выявленные узкие места

### 1. Блокирующая генерация всей недели на онбоардинге
- **Проблема**: Генерировалось сразу 3-7 дней, что блокировало переход на главную страницу
- **Решение**: Генерируется только первый день (~2-3 секунды), остальные дни генерируются на главной странице в фоне

### 2. Неправильная логика отображения на главной странице
- **Проблема**: 
  - Первый день не отображался из кеша немедленно
  - Условие `if (dayIndex > 0)` пропускало потоковое отображение для первого дня
  - Метод `_ensureWorkoutsAvailable` был блокирующим
- **Решение**: 
  - Главная страница немедленно читает и отображает первый день из кеша
  - Убрана блокирующая логика - генерация запускается асинхронно
  - Остальные дни генерируются параллельно в фоне

### 3. Медленная генерация каждого дня
- **Проблема**: Каждый день ждал полного завершения стрима и финального JSON
- **Решение**: Генерация останавливается после получения 6-7 упражнений, не дожидаясь финального JSON

### 4. Статичные шимеры
- **Проблема**: Использовались серые контейнеры без анимации
- **Решение**: Добавлены анимированные шимеры с эффектом пульсации

## Архитектурные изменения

### Онбоардинг (`train_plan_screen.dart`)
```dart
// БЫЛО: Генерация всех 3-7 дней последовательно
for (int dayIndex = 0; dayIndex < totalDays; dayIndex++) {
  final day = await _generateOneDay(...);
  allDays.add(day);
}

// СТАЛО: Генерация только первого дня
final firstDay = await _generateOneDayWithProgress(0, totalDays);
// Остальные дни будут сгенерированы на главной странице
```

**Оптимизация генерации:**
- Добавлена досрочная остановка после 6 упражнений
- Сокращено время генерации первого дня с ~10-15 секунд до ~2-3 секунд

### Главная страница (`home_screen.dart`)
```dart
// БЫЛО: Блокирующая генерация всех дней последовательно
Future<void> _ensureWorkoutsAvailable(...) async {
  for (int dayIndex = startFromDay; dayIndex < totalDays; dayIndex++) {
    await service.streamNextMissingDay(...);
  }
}

// СТАЛО: Немедленное отображение + параллельная фоновая генерация
void _ensureWorkoutsAvailable(...) {
  Future.microtask(() async {
    // Параллельная генерация всех недостающих дней
    final tasks = [
      for (int i = startFromDay; i < totalDays; i++)
        _generateDayInBackground(...)
    ];
    await Future.wait(tasks);
  });
}
```

**Ключевые улучшения:**
- Метод стал `void` - не блокирует UI
- Генерация запускается через `Future.microtask`
- Все дни генерируются параллельно (`Future.wait`)
- Первый день немедленно отображается из кеша

### Сервис генерации (`weekly_workout_plan_service.dart`)
```dart
// БЫЛО: Ожидание полного завершения стрима
finalPlan = await _generateOneDay(...);

// СТАЛО: Досрочная остановка после 6 упражнений
if (interim.length >= targetExercises &&

```

- ✅ Параллельная генерация остальных дней не блокирует UI

### Технические улучшения
- ✅ Сокращено время ожидания на ~80%
- ✅ Убраны блокирующие операции из UI-потока
- ✅ Параллельная генерация вместо последовательной

## Best Practices применённые в решении

1. **Non-blocking UI**: Все долгие операции выполняются асинхронно
2. **Progressive Loading**: Показываем данные по мере их получения
3. **Parallel Processing**: Генерация дней выполняется параллельно
4. **Early Termination**: Останавливаем генерацию как только получено достаточно данных
5. **Cache-first Strategy**: Сначала проверяем кеш, потом запрашиваем новые данные
6. **Animated Feedback**: Динамические шимеры показывают процесс загрузки

## Дополнительное исправление: согласованность weekStart и расписания

### Проблема
После первой оптимизации обнаружилась проблема: первый день не отображался на главной странице.

**Причина:** несоответствие между:
- `weekStart` в модели (понедельник недели для ключа хранения)
- База расписания (дата прохождения онбоардинга, может быть любой день)

**Пример:** Если онбоардинг прошли в четверг 03.10:
- План сохранялся с `weekStart = 03.10` (четверг)
- Репозиторий вычислял ключ через `startOfWeek()` → 29.09 (понедельник)
- На главной странице тренировочные дни вычислялись от `weekStart` (понедельник)
- Четверг не входил в паттерн Пн-Ср-Пт → тренировка не находилась

### Решение
1. **Онбоардинг:** Сохранять план с `weekStart = startOfWeek(today)` (понедельник недели)
2. **Главная страница:** 
   - Вычислять тренировочные дни от даты установки (не от `weekStart`)
   - Всегда включать первый день (дату онбоардинга) в расписание

```dart
// Онбоардинг
final weekStartMonday = startOfWeek(planStart);  // Понедельник для ключа
final weeklyPlan = WeeklyWorkoutPlanModel(
  weekStart: weekStartMonday,  // Для согласованности с репозиторием
  days: [firstDay],
);

// Главная страница
final scheduleBase = _getCalendarStartDate();  // Дата установки/онбоардинга
final scheduledDates = _computeScheduledDates(scheduleBase, ...);
dates.add(startDate);  // Всегда включаем первый день!
```
