# Исправление потокового отображения тренировок

## 🎯 Проблема

После перехода на второй и третий день пользователь видел:
1. **День 2**: 6 одинаковых упражнений (дубликаты первого упражнения), затем данные менялись на правильные
2. **День 3**: Долгая загрузка шиммеров, затем данные появлялись сразу все (не потоково)

## 🔍 Причины

### 1. Перезапись данных в `complete()`
В методе `WorkoutDayStreamingNotifier.complete()` при вызове с `finalPlan` полностью перезаписывалось состояние, затирая промежуточные упражнения, которые уже были добавлены через `addExercise()`.

### 2. Отсутствие очистки провайдера
Провайдер `workoutDayStreamingProvider` с `autoDispose` не очищался явно перед началом генерации нового дня, что могло привести к "протечке" данных из предыдущей генерации.

### 3. Дублирование упражнений
Метод `addExercise()` не проверял наличие упражнения с таким же именем перед добавлением, что приводило к дубликатам.

### 4. Отсутствие задержки между днями
Дни генерировались один за другим без визуальной паузы, что затрудняло восприятие потокового отображения.

### 5. Несогласованность ключей провайдера
Ключи провайдера в разных местах формировались по-разному, что могло привести к конфликтам.

## ✅ Решение

### 1. Исправлен `WorkoutDayStreamingNotifier`

```dart
// Добавлен метод для явной очистки
void reset() {
  if (!mounted) return;
  state = const WorkoutDayStreamingState();
}

// Улучшен метод добавления упражнения
void addExercise(ExerciseItem ex) {
  if (!mounted) return;
  // Проверяем дубликаты перед добавлением
  final exists = state.exercises.any((e) => e.name == ex.name);
  if (exists) {
    // Обновляем существующее упражнение
    final updated = state.exercises.map((e) => e.name == ex.name ? ex : e).toList();
    state = state.copyWith(exercises: updated, isActive: true);
  } else {
    // Добавляем новое
    final List<ExerciseItem> next = List<ExerciseItem>.from(state.exercises)..add(ex);
    state = state.copyWith(exercises: next, isActive: true);
  }
}

// Исправлен метод завершения - НЕ перезаписывает данные
void complete({WorkoutPlanModel? finalPlan}) {
  if (!mounted) return;
  // Просто отмечаем как неактивный, не перезаписываем данные
  state = state.copyWith(isActive: false);
}
```

**Ключевые изменения:**
- ✅ Добавлен метод `reset()` для явной очистки состояния
- ✅ `addExercise()` теперь проверяет дубликаты по имени
- ✅ `complete()` не перезаписывает данные, только меняет флаг `isActive`

### 2. Обновлен `BackgroundWorkoutGenerationService`


**Ключевые изменения:**

- ✅ Явный вызов `reset()` перед началом генерации
- ✅ Задержка 100мс после `reset()` для корректной очистки
- ✅ Задержка 500мс между днями для визуального разделения
- ✅ Улучшенное логирование с разделителями

## 🏗️ Архитектура потокового отображения

### Последовательность событий для каждого дня:

```
1. [СЕРВИС] Отмечаем начало генерации дня
   └─> weekGenerationState.startDayGeneration(dayIndex)

2. [ПРОВАЙДЕР] Создаем уникальный ключ
   └─> streamingKey = 'workout_day_{timestamp}_{dayIndex}'

3. [ПРОВАЙДЕР] Очищаем состояние
   └─> reset() → state = пустой WorkoutDayStreamingState

4. [ЗАДЕРЖКА] 100мс для корректной очистки

5. [ПРОВАЙДЕР] Запускаем стриминг
   └─> start() → state = {isActive: true, exercises: []}

6. [LLM СТРИМ] Начинаем получать чанки от модели
   ├─> onTitle(title) → setTitle(title)
   └─> onExercise(ex) → addExercise(ex) // с проверкой дубликатов

7. [UI] Отображаем упражнения по мере добавления
   └─> ref.watch(workoutDayStreamingProvider(streamingKey))

8. [ЗАВЕРШЕНИЕ] Помечаем стриминг как завершенный
   └─> complete() → state.copyWith(isActive: false)

9. [СОХРАНЕНИЕ] Сохраняем полный план дня в репозиторий

10. [ОБНОВЛЕНИЕ] Инвалидируем провайдер плана недели
    └─> ref.invalidate(weeklyWorkoutPlanForDateProvider)

11. [ЗАДЕРЖКА] 500мс перед следующим днем
```

### Защита от дублирования:

```dart
void addExercise(ExerciseItem ex) {
  final exists = state.exercises.any((e) => e.name == ex.name);
  if (exists) {
    // ОБНОВЛЯЕМ существующее (например, если вес уточнился)
    final updated = state.exercises
        .map((e) => e.name == ex.name ? ex : e)
        .toList();
    state = state.copyWith(exercises: updated);
  } else {
    // ДОБАВЛЯЕМ новое
    state = state.copyWith(
      exercises: [...state.exercises, ex]
    );
  }
}
```

### Формат ключа провайдера:

```
workout_day_{weekStartTimestamp}_{dayIndex}

Пример: workout_day_1729800000000_1
         ^^^^^^^^^^  ^^^^^^^^^^^^^ ^^^
         префикс     неделя        индекс дня (0-6)
```

**Почему это важно:**
- ✅ Уникальность для каждого дня недели
- ✅ Один ключ используется везде (сервис, UI, fallback)
- ✅ `autoDispose` корректно очищает старые провайдеры

## 🎨 UX Улучшения

1. **Плавный переход между днями**: Пауза 500мс позволяет пользователю осознать завершение одного дня и начало следующего

2. **Чистое состояние**: Каждый день начинается с пустого экрана (заголовок + шиммеры), затем постепенно заполняется упражнениями

3. **Без дубликатов**: Если LLM присылает обновленную версию упражнения (например, уточненный вес), мы обновляем существующее, а не добавляем дубликат

4. **Детальное логирование**: Разделители и эмодзи помогают отследить процесс генерации в консоли
