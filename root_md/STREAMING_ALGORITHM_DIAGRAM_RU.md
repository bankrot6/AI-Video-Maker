# 🔄 Диаграмма алгоритма потокового отображения

## 📊 Общая архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                     ONBOARDING SCREEN                        │
│                                                               │
│  1. Собирает данные пользователя                            │
│  2. Генерирует ТОЛЬКО день 1                                │
│  3. Сохраняет weeklyFocuses для дней 2-N                    │
│                                                               │
│  Output: UserModel + WeeklyWorkoutPlan (1 день)             │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
                   USER NAVIGATES
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                      HOME SCREEN                             │
│                                                               │
│  • Отображает день 1 (готов)                                │
│  • Запускает фоновую генерацию дней 2-N                     │
│  • Слушает потоковые обновления через провайдеры             │
│                                                               │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│          BACKGROUND WORKOUT GENERATION SERVICE               │
│                                                               │
│  • Генерирует дни 2-N ПОСЛЕДОВАТЕЛЬНО                       │
│  • Каждый день = отдельный LLM запрос                       │
│  • Обновляет провайдер в реальном времени                   │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

```dart

```

## 📦 Структура провайдера

```
WorkoutDayStreamingState {
  String? dayTitle         // "День 2: Грудь"
  List<Exercise> exercises // [ex1, ex2, ...]
  bool isActive            // true = идет генерация
}

┌─────────────────────────────────────────┐
│  WorkoutDayStreamingNotifier            │
├─────────────────────────────────────────┤
│  reset()       → Очистка состояния      │
│  start()       → isActive = true        │
│  setTitle()    → Обновляет заголовок    │
│  addExercise() → Добавляет/обновляет    │
│  complete()    → isActive = false       │
└─────────────────────────────────────────┘
```

## 🔑 Формат ключа провайдера

```
workout_day_{weekStartTimestamp}_{dayIndex}
     ↓             ↓                  ↓
  префикс    уникальная      порядковый номер
             неделя          дня (0-6)

Пример:
  workout_day_1729800000000_0  → День 1 (понедельник)
  workout_day_1729800000000_1  → День 2 (среда)
  workout_day_1729800000000_2  → День 3 (пятница)

Важно:
  ✅ Один ключ = один день одной недели
  ✅ Разные недели = разные ключи
  ✅ autoDispose очищает старые провайдеры
```

## 🔄 Жизненный цикл провайдера

```
┌─────────────────────────────────────────────────────────┐
│                   PROVIDER LIFECYCLE                     │
└─────────────────────────────────────────────────────────┘

1. СОЗДАНИЕ
   ↓
   ref.watch(workoutDayStreamingProvider(key))
   ↓
   new WorkoutDayStreamingNotifier()
   ↓
   state = WorkoutDayStreamingState() // пустой

2. ОЧИСТКА (явная)
   ↓
   provider.reset()
   ↓
   state = WorkoutDayStreamingState() // гарантированно пустой
   ↓
   await 100ms

3. ЗАПУСК
   ↓
   provider.start()
   ↓
   state = {isActive: true, exercises: []}

4. ОБНОВЛЕНИЯ (множественные)
   ↓
   provider.setTitle("...")
   provider.addExercise(ex1)
   provider.addExercise(ex2)
   ...
   ↓
   state обновляется → UI ререндерится

5. ЗАВЕРШЕНИЕ
   ↓
   provider.complete()
   ↓
   state = {isActive: false, остальное без изменений}

6. АВТООЧИСТКА (autoDispose)
   ↓
   Когда UI больше не слушает провайдер
   ↓
   Провайдер удаляется из памяти
```

## 📈 Метрики производительности

```
┌──────────────────────────┬──────────┬────────────┐
│        Операция          │  Время   │  Тип       │
├──────────────────────────┼──────────┼────────────┤
│ reset()                  │  <1мс    │ Синхронная │
│ Задержка после reset()   │  100мс   │ Фиксир.    │
│ start()                  │  <1мс    │ Синхронная │
│ LLM: первый чанк         │  2-5с    │ Сеть       │
│ LLM: чанк упражнения     │  1-3с    │ Сеть       │
│ setTitle()               │  <1мс    │ Синхронная │
│ addExercise()            │  <1мс    │ Синхронная │
│ complete()               │  <1мс    │ Синхронная │
│ saveDayAtIndex()         │  <10мс   │ Диск       │
│ Задержка между днями     │  500мс   │ Фиксир.    │
└──────────────────────────┴──────────┴────────────┘

Общее время генерации одного дня: ~10-20 секунд
  - Зависит от LLM и сети
  - 6 упражнений × 1-3с каждое
```

## 🐛 Сценарии ошибок

```
┌──────────────────────────────────────────────────────┐
│              ОБРАБОТКА ОШИБОК                         │
└──────────────────────────────────────────────────────┘

1. LLM недоступен
   ↓
   try-catch в generateDay()
   ↓
   Логируем ошибку
   ↓
   weekGenState.completeDayGen() // помечаем как завершенный
   ↓
   Продолжаем следующий день

2. Невалидный JSON от LLM
   ↓
   Парсер возвращает пустой список
   ↓
   День сохраняется с 0 упражнений
   ↓
   UI: fallback генерация при повторном открытии

3. Context unmounted
   ↓
   Проверка if (!context.mounted)
   ↓
   Прерываем генерацию
   ↓
   При следующем открытии → fallback

4. Провайдер dispose
   ↓
   if (!mounted) return в каждом методе
   ↓
   Безопасный выход
```
