# Исправления функции замены упражнений

## Обзор исправлений

Исправлены две критические проблемы в функции замены упражнений:

1. ✅ **Изменения не сохранялись** при выходе из режима менеджмента
2. ✅ **Невозможность множественной замены** упражнений

---

## Проблема 1: Изменения не сохранялись

### Описание проблемы

При нажатии на кнопку "Готово" в режиме менеджмента:
- Изменения упражнений (включая замены) не сохранялись в репозиторий
- После выхода и повторного входа все изменения исчезали
- UI возвращался к исходному состоянию

### Решение

Реализован метод `_saveManagementChanges()`, который:

1. **Получает контекст**:
   - Данные пользователя (для `workoutsPerWeek`)
   - Текущий план недели
   - Дату изменяемой тренировки

2. **Вычисляет индекс дня**:
   ```dart
   final scheduledDates = _computeScheduledDates(
     _managedExercisesDate!,
     workoutsPerWeek,
     weeksForward: 0,
     weeksBackward: 0,
   );
   
   final dateIndex = scheduledDates.indexWhere(
     (date) => _isSameDate(date, _managedExercisesDate!),
   );
   
   final dayIndexInWeek = dateIndex % workoutsPerWeek;
   ```

3. **Создает обновленный план дня**:
   ```dart
   final updatedDayPlan = WorkoutPlanModel(
     dayTitle: dayTitle,
     exercises: List<ExerciseItem>.from(_managedExercises),
   );
   ```

4. **Сохраняет в репозиторий**:
   ```dart
   final repository = ref.read(weeklyWorkoutPlanRepositoryProvider);
   await repository.saveDayAtIndex(
     weekStart,
     updatedDayPlan,
     dayIndexInWeek,
     workoutsPerWeek,
   );
   ```

5. **Обновляет UI**:
   ```dart
   ref.invalidate(home_providers.weeklyWorkoutPlanForDateProvider(weekStart));
   ```

6. **Показывает подтверждение**:
   - Успешное сохранение: "Изменения сохранены"
   - Ошибка: "Не удалось сохранить изменения"

### Интеграция в `_exitManagementMode()`

```dart
Future<void> _exitManagementMode() async {
  // Сохраняем изменения перед выходом
  if (_managedExercisesDate != null && _managedExercises.isNotEmpty) {
    await _saveManagementChanges();
  }
  
  setState(() {
    _isManagementMode = false;
    _managedExercisesDate = null;
    _managedExercises = [];
    _replacingExercises.clear(); // Очищаем состояние замены
  });
  
  HapticFeedback.mediumImpact();
}
```

### Логи отладки

При сохранении выводятся логи:
- `💾 SAVE_MANAGEMENT: Начинаем сохранение изменений`
- `💾 SAVE_MANAGEMENT: Дата: [дата]`
- `💾 SAVE_MANAGEMENT: Упражнений: [количество]`
- `💾 SAVE_MANAGEMENT: Индекс дня в неделе: [индекс]`
- `✅ SAVE_MANAGEMENT: Изменения успешно сохранены`

При ошибках:
- `❌ SAVE_MANAGEMENT: Нет данных пользователя`
- `❌ SAVE_MANAGEMENT: План недели не найден`
- `❌ SAVE_MANAGEMENT: Дата не найдена в расписании`
- `❌ SAVE_MANAGEMENT: Ошибка сохранения: [текст ошибки]`

## Проблема 2: Невозможность множественной замены

### Описание проблемы

После замены одного упражнения:
- Невозможно было заменить другие упражнения
- Кнопка замены становилась неактивной
- Состояние `_replacingExercises` не очищалось

### Решение

1. **Очистка состояния при выходе**:
   ```dart
   _replacingExercises.clear(); // в _exitManagementMode()
   ```

2. **Корректная обработка завершения замены**:
   ```dart
   if (newExercise != null) {
     setState(() {
       _managedExercises[index] = newExercise;
       _replacingExercises.remove(index); // Удаляем только текущий индекс
     });
   }
   ```

3. **Async callbacks для корректной работы Future**:
   ```dart
   // До:
   onTap: _exitManagementMode,
   
   // После:
   onTap: () => _exitManagementMode(),
   ```

### Теперь работает

- ✅ Можно заменить любое количество упражнений подряд
- ✅ Каждая замена обрабатывается независимо
- ✅ Состояние корректно очищается после каждой операции
- ✅ При выходе из режима все состояния сбрасываются

## Известные ограничения

1. **Требуется план недели**: 
   - Если план недели не существует, сохранение не произойдет
   - Это нормальное поведение, так как нельзя сохранить день без недели

2. **Async операция**:
   - Сохранение занимает ~100-300мс
   - На медленных устройствах может быть дольше

3. **Проверка workoutsPerWeek**:
   - Используется значение по умолчанию (3) если не указано
   - Это безопасно, но может быть неожиданным
